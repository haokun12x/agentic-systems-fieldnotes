The model doesn’t follow a fixed script. It picks a tool and gives it arguments… …reads the result, and decides again. A weak result changes the next query. When the evidence is good enough — or a tool reports a clear gap — the loop ends.
STEP 4 · THREE PLACES FOR FILES
One file API. Three storage contracts.
STATE{ }Drafts & reports/plan.md · /final_report.md

Live in the conversation state. Saved with checkpoints, not as OS files.

DISK▤Uploads/workspace/input.pdf

Real bytes on disk, per department and thread. OCR and audio tools read them.

READ-ONLY◇Approved knowledge/knowledge/policy.md

The Agent can read it. Writes, edits and uploads are rejected.

✕ write_file → rejected: read-only
Files look alike to the Agent, but each kind has its own owner and lifetime — so drafts never overwrite evidence.
