03 / FILES & STORAGEOBSERVED IMPLEMENTATION · EXPLAINED AS A MODEL

One workspace.
Three storage contracts.

A draft can look like a file without being an OS file. The runtime routes virtual paths to conversation state, uploaded bytes, or curated knowledge. Each has a different owner, access path, and lifetime.

IN PLAIN TERMSFiles the Agent “sees” live in three different places: drafts in the conversation state, uploads on disk, and approved knowledge that is read-only. Each has a different owner and a different lifetime.

IMPLEMENTED PATTERN

Follow a file through the boundary.

Examples use synthetic content.

Root-level drafts are graph-state entries. Uploaded files use per-thread disk storage. Curated knowledge is read-only.

WHAT HAPPENS

A composite backend routes paths without requiring the caller to know where the content is stored.

WHY THE BOUNDARY EXISTS

Working context, original evidence, and approved knowledge should not silently overwrite one another.

STORAGE TYPE ≠ RETENTION POLICY

{ }STATE-BACKED

Plans, drafts & reports

/plan.md · /final_report.md

Entries inside the graph’s files state. File tools return state updates; they do not create matching files at the host’s root.

SAME THREADThe next step reads the latest state.

Checkpointing can persist this state to disk or a database. “In memory” describes the access model, not a promise that bytes never reach disk.

▤DISK-BACKED

Uploads & derived sidecars

/workspace/input.pdf

Physical files resolved under the selected department and thread directory. OCR, audio, and table tools use these concrete paths.

SAME THREADThe next tool reads the same stored bytes.

The examined implementation defaults workspace TTL to zero: automatic expiry is off. Retained files still need backup, deletion policy, and capacity management.

◇READ-ONLY

Curated knowledge

/knowledge/policy.md

A separate disk mount exposed through a wrapper that rejects writes, edits, and uploads from the agent.

SOURCE CONTROLLEDRead the approved source version.

Read-only is an access rule, not a storage medium. Content updates belong to a separate knowledge-maintenance workflow.

A single virtual file API can sit over three independent stores. It does not make their writes one atomic transaction.

WHAT “THINKING IN MEMORY” MEANS HERE

Explicit reflection and saved drafts are application data: the reflection tool returns a conversation message, while plans and reports update the graph’s file state. These interfaces do not establish that private model-internal reasoning is exposed or durably recorded.

FROM A PERSONAL AGENT TO A SERVICE

The machine is shared.
The authority is not.

A local single-user agent often inherits the operator’s working directory and OS identity. A hosted service has to resolve the caller, department, and thread before selecting a workspace.

02 / EXECUTION

The examined agent does not expose an arbitrary shell. Controlled server adapters invoke tools such as Pandoc and ffmpeg with materialized files.

03 / ISOLATION

A virtual route is an application boundary. OS permissions, process isolation, credentials, and container controls are separate security layers.
